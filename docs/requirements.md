# カラオケ持ち歌管理・評価アプリ 要件定義

## 1. コンセプト
カラオケに行ったとき「この曲、上手く歌えるか？」をパッと出すための個人用PWA。
持ち歌を登録し、曲ごとの「歌える度」と機械採点の点数を記録しておく。
SNS的な共有や他人との比較は持たない、自分だけのクローズドなデータベース。
カラオケ店の室内で片手でさっと引ける操作感を最優先する。評価は細かく分けず、一目で判断できることを重視する。

## 2. 技術スタック
- React + TypeScript、ビルドは esbuild（依存を最小限にしてスマホ運用で壊れにくくするため）
- IndexedDB（自前の薄いラッパー、ローカルファースト）。利用者ごとに別DB
- PWA：manifest ＋ 自前の Service Worker（オフライン動作、ビルドごとにキャッシュ更新）
- Google Drive バックアップ（自動＋手動、マイドライブ内の「カラオケ持ち歌バックアップ」フォルダ、drive.file スコープ）
- 複数利用者対応：各自が自分の端末・自分のGoogleアカウントで使い、データは個人ごと。端末間同期は「Driveから復元」で足りる
- 曲情報の取得：iTunes Search API（`country=JP&entity=song&lang=ja_jp`、APIキー不要、JSONP）
- ホスティング：GitHub Pages（main への push で GitHub Actions がテスト→ビルド→公開）
- 開発・運用はスマホ完結（Claudeアプリから依頼 → Claudeが push → 自動公開）
- モバイルファースト。ダークテーマ基調（カラオケ店の暗い室内で眩しくない）

## 3. データモデル

### Song（持ち歌）
| 項目 | 型 | 備考 |
|---|---|---|
| id | string | |
| title | string | 必須 |
| titleKana | string? | 読み（検索用、任意入力） |
| artist | string | 必須 |
| artistKana | string? | 読み（検索用、任意入力） |
| artworkUrl | string? | iTunes取得時のジャケット |
| itunesTrackId | number? | 重複登録チェック用 |
| rating | 1〜5 | **歌える度**（★1つの評価のみ）。★5=十八番、★3=無難に歌える、★1=練習中 |
| key | number | -12〜+12、既定0 |
| preferredMachine | 'DAM' \| 'JOYSOUND' \| 'どちらでも' | |
| mood | '盛り上がる' \| 'ミディアム' \| 'しっとり' \| null | 曲調 |
| tags | string[] | 自由タグ（例：会社用、友達と） |
| favorite | boolean | |
| memo | string | |
| createdAt / updatedAt | Date | |

### ScoreLog（歌唱ログ・1回歌うごとに1件）
| 項目 | 型 | 備考 |
|---|---|---|
| id | string | |
| songId | string | |
| date | Date | 既定は今日 |
| machine | 'DAM' \| 'JOYSOUND' \| 'その他' | |
| scoringMode | string? | 例：精密採点Ai、分析採点AI（自由入力＋過去入力からサジェスト） |
| score | number? | 0〜100、小数3桁まで（採点なしで歌った記録も可） |
| keyUsed | number | 既定は Song.key |
| memo | string? | |

派生値（保存せず算出）：最高点、直近点、歌唱回数、最終歌唱日。

## 4. 画面構成（ボトムナビ5画面）

### ① 持ち歌一覧（ホーム）
- 上部に検索バー：曲名・アーティスト名・読みを横断検索
- 絞り込み：歌える度（★いくつ以上）、アーティスト、タグ、曲調、機種、お気に入り
- 並び順：歌える度順（既定）／アーティスト順（同じアーティストをまとめてセクション表示）／曲名順／最高点順／最終歌唱日順／登録日順
- 各行：曲名・アーティスト・★歌える度（大きく目立たせる）・キー（例 -2）・最高点
- 点数の表示/非表示トグル（人に画面を見せるとき用）
- アーティストタップでそのアーティストの曲だけに絞り込み

### ② 曲を追加
- iTunes検索：キーワード入力→候補リスト（ジャケット・曲名・アーティスト）→タップで取り込み
- 手入力も可（カラオケ限定曲など）
- 登録済みの曲は候補に「登録済み」表示
- 追加時に歌える度・キー・曲調・タグまでまとめて入力できる（必須は歌える度のみ）
- 「続けて登録」トグル：保存後に検索画面へ戻り、連続登録できる

### ③ おまかせ選曲
- 条件（歌える度・タグ・曲調・機種）を指定してランダムに1曲提示
- 「もう1曲」ボタン、選んだ曲からそのまま歌唱ログ追加へ

### ④ 記録
- 最近の歌唱ログ一覧（日付ごと）
- 全体：持ち歌数、歌える度の内訳、よく歌う曲トップ10、最高点トップ10

### ⑤ 設定
- Googleドライブ バックアップ／復元（自動＋手動）
- CSVインポート／エクスポート（曲とログ）
- タグ管理（名前変更・削除・統合）
- 利用者切り替え

### 曲詳細画面（一覧からタップ）
- 全項目の表示・編集（歌える度は★をタップで即変更）
- 「歌った！」ボタン → 歌唱ログ追加シート（機種・モード・点数・キー、最小限の入力で保存）
- その曲の歌唱ログ一覧と得点推移の折れ線グラフ（機種別に色分け）
- 外部リンク：YouTubeで検索、歌詞を検索（曲名＋アーティストでGoogle検索を開くだけ）

## 5. 検索の表記ゆれ対策
以下を正規化してから部分一致で照合する。
- ひらがな／カタカナを同一視
- 全角／半角、英大文字／小文字を同一視
- 長音記号「ー」と母音（例：ありがとー／ありがとう）を同一視
- 「ヴ」↔「ブ」、小さい文字↔通常文字を同一視
- スペース・記号を無視

## 6. 実装しないもの
- 細かい自己評価軸（音程・リズム等の多軸評価）。評価は「歌える度」の★1つのみ
- 録音機能（容量と手間が重い）
- 音域判定・音域データ
- 他ユーザーとの共有・ランキング・SNS連携
- 機械採点の詳細項目（ビブラート回数、しゃくり等）の記録 ※メモ欄で代用
- カラオケ機種への選曲予約連携

## 7. 受け入れ条件
- iTunes検索から曲を取り込み、歌える度・キー・タグ付きで保存できる
- 曲名・アーティスト名・読みで、ひらがな/カタカナや長音のゆれがあっても検索できる
- 一覧を開いた瞬間に、歌える度の高い順で★とキーが一目で見える
- 歌える度・アーティスト・タグ・曲調で絞り込み、指定の並び順で表示できる
- 歌唱ログを3タップ程度で追加でき、最高点・推移グラフに反映される
- オフラインで一覧・検索・ログ追加ができる
- Driveへのバックアップと別端末での復元ができる
- CSVで書き出したデータを読み込み直して元に戻せる

## 8. 進め方
1. データモデルと IndexedDB、一覧・検索・手入力登録まで
2. iTunes検索取り込み、曲詳細
3. 歌唱ログと得点推移グラフ、記録画面
4. おまかせ選曲、CSV入出力
5. Driveバックアップ、複数利用者、PWA化、GitHub Pages 自動デプロイ
各ステップ完了ごとに動作確認できる状態でコミットすること。
